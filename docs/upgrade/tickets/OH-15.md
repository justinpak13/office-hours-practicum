Git reports conflicts in 3 files. Resolve them like this:

**1. Root `package.json`.** Keep the backend's Percy packages, and use typescript-eslint 5.62:

```json
    "@percy/cli": "^1.32.12",
    "@percy/cypress": "^3.1.9",
    "@typescript-eslint/eslint-plugin": "^5.62.0",
    "@typescript-eslint/parser": "^5.62.0",
```

Leave `"eslint": "^8.57.0"` as it is (it merges by itself). typescript-eslint 8 plus TypeScript 5.9 gave 18 new lint errors from its stricter default rules. 5.62 works with ESLint 8 and gives 0 errors. Upgrading the lint rules is phase 3 work.

**2. `packages/server/package.json`, first conflict.** Take the backend side, which keeps only:

```json
    "nestjs-command": "^2.0.0",
```

(`nestjs-admin` and `nestjs-redis` stay removed.)

**3. `packages/server/package.json`, second conflict.** Keep only:

```json
    "typescript": "^5.9.3",
```

(`typeorm-factory` stays removed.)

**4. `packages/app/package.json`.** Not a conflict, but needed: change `"eslint-plugin-react-hooks": "^4.1.0"` to `"eslint-plugin-react-hooks": "^4.6.2"`. The old version crashes ESLint 8 ("Rules with suggestions must set the meta.hasSuggestions property"). This crash already happens on the backend branch today.

**5. `yarn.lock`.** Don't edit it by hand:


## Issues found on upgrade-backend-justin (they exist before the merge too)

1. **The server crashes on startup in development: `Error: ADMIN_SESSION_SECRET must be set`.** `packages/server/src/admin/admin-session.ts` reads `process.env.ADMIN_SESSION_SECRET` the moment the file loads. That's before Nest reads `.env.development`. Workaround to test: `set -a; . packages/server/.env.development; set +a` before `yarn dev`. Fix: read the secret inside a function called after the config module has loaded, or load the env file at the very top of `main.ts`.
2. **Adding a question to an empty queue fails, and live updates stop.** `packages/server/src/question/question.subscriber.ts` now calls `QueueModel.findOne({ where: { id: event.entity.queueId }, relations: ['staffList'] })`. When `queueId` isn't set on the new entity, this returns nothing, and `.staffList` crashes (`Cannot read properties of undefined (reading 'staffList')`). The old `findOne(id, ...)` call hid this. Seen as a 500 from `/api/v1/seeds/fill_queue`, and the TA's queue doesn't update. Likely fix, untested: use `event.entity.queueId ?? event.entity.queue?.id`, and skip when there's no queue. Check smoke-test steps 3–4 after fixing.
3. **The branch says Node 18,** which is out of support. After this merge the repo requires Node 22.12 or later (from OH-04), and every test above ran on Node 22.

Also seen in the dev log, without stopping the server: ts-loader 8 printing `Debug Failure ... resolveTypeReferenceDirective` with TypeScript 4.9. It's worth upgrading ts-loader to 9 in phase 3.
